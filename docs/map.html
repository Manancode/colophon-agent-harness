Colophon — plain English

How the thing works

Colophon turns a written description of a video into a video, then argues with itself about whether the result is any good. This page is the whole system on one screen.

01 The journey of one video

Four things get made, and keeping them apart is the central design decision. When one file is simultaneously the plan, the project, the asset store and the timeline, you cannot validate, compare or hash any part of it independently — which is exactly the situation this project was extracted from.

The one rule

The spec is written once and never rewritten. Attempts only ever read it. That single rule is what makes “which spec made this video?” answerable with one command instead of an archaeology session.

02 The fourteen gates

These are the health inspector. No gate calls an AI model — each one is a rule you could check by hand, which is precisely why they can be trusted to block a release.

Work on paper — 4 gates

Need nothing but the spec. Run before spending a second of render time.

1
spec_validate

Unknown values, missing fields, malformed structure. “Your recipe mentions an ingredient we don’t stock.”

2
timeline_continuity

Gaps between scenes, overlaps nobody declared, scenes scheduled off the end of the clock.

3
narrative_order

Structurally odd running order — a call-to-action in the opening beat, say. Advisory only: it comments, it does not block.

4
delivery_contract

The result isn’t actually a deliverable video: wrong canvas or frame rate, wrong length, sub-second scene, duplicate IDs.

Need a real artifact — 10 gates

Read the emitted project or the encoded MP4.

5
static_html

Lint on the markup: duplicate attributes, inline JavaScript handlers, remote asset links, fonts without a local source.

6
canvas_audit

Background colour is the brand colour, and text isn’t invisible against it.

7
scene_structure

Something is scheduled on the clock but draws nothing — a blank scene or a missing asset.

8
claim_grounding

Every number and claim on screen traces back to a source you supplied. Nothing is invented.

9
ai_slop_detector

The generic-AI look: cream-and-orange palette, sparkle glyphs in the copy, neon glow or ticker bar in the CSS.

10
color_consistency

The emitted accent colour is the brand accent, not a nearby hue someone eyeballed.

11
centerpiece_invariant

Exactly one motion focal point per scene. Two competing animations read as noise.

12
motion_accessibility

No opt-out for people who asked their OS to reduce motion, or motion fast enough to read as flicker.

13
motion_pixel_velocity

Motion slower than about 1 pixel per frame visibly stutters — screens can’t render half a pixel.

14
media_contract

The file on disk matches the promise: resolution, frame rate, duration. Catches “the render succeeded but produced the wrong video”.

03 What a failure means

A gate reporting a problem is not the same as the run being unshippable. The difference isn’t guessed from the wording of the message — it is looked up in a fixed registry. Every run ends in one of three states.

ready

Nothing to report. Ship it.

ready_with_warnings

Only advisories. Worth a reviewer’s attention, still ships.

blocked

At least one blocker — or something the registry doesn’t recognise.

Why an unrecognised problem blocks

A system that classifies problems by matching their text gets more permissive exactly when it is confused: a new kind of problem matches no rule, gets filed as “unknown but presumably minor”, and ships. Inverting the default fixes it. An unrecognised problem is not evidence that something is safe — it is evidence that we don’t know what it is — so it blocks. Forgetting to register a code costs you a blocked run you notice immediately, rather than a shipped defect you notice in production.

05 The four places you can swap something out

Colophon is built so the parts most likely to change sit behind a seam. Each has a working default and a documented interface — and the pipeline runs to completion with any of them deleted.

Renderer

default: the HTML/CSS adapter

The only place in the codebase allowed to know what HTML and CSS are.

Swap in: a different way to turn a spec into pixels.

Reviewer

default: contact sheet + recorded verdicts

QA is deterministic and machine-run; review is independent. They share no code.

Swap in: a different critic — human, model, or rubric.

Repair agent

default: not wired

Mechanical fixes run automatically. Judgement calls stop the loop and report rather than guess.

Swap in: a model that proposes spec edits. Off by default on purpose.

Bench agent

default: skipped unless --agents

Running a coding agent costs money, needs network, and can’t be reproduced.

Swap in: another coding agent to compare against.

06 Glossary

Every term decoded, with the concrete example from this project.

Spec
The recipe. A JSON file describing scenes, timing, text and colours. The single source of truth; everything else is derived from it.
Emit
Turning the spec into an editable project before rendering, so the markup can be inspected and checked without paying for an encode.
Attempt
One numbered try inside a run directory. Attempts are disposable; the spec is not.
Gate / Stage
One deterministic check. Pass or fail, with reasons. No opinions. “Stage” is the code that implements a gate.
Blocker vs advisory
A blocker stops the run. An advisory is worth reading but still ships.
Fails closed
When in doubt, say “stop” rather than “go”. An unrecognised problem blocks rather than being waved through.
Taxonomy
The fixed registry of failure codes and their severities. If a problem’s code isn’t in it, the run blocks.
Grounding
Every claim on screen must trace back to a source you supplied. Nothing is invented at render time — treatments can only arrange the copy you gave them, which makes an unbound number structurally impossible rather than merely detected afterwards.
Treatment
A named motion behaviour for a scene — a word-by-word sweep, a thinking pulse. A bounded set, each with preconditions.
Role
What a scene is for: hook, problem, solution, proof, call to action. Roles have a sensible order, and gate 3 checks you didn’t put the call to action first.
Canvas audit
The background-colour check. It walks ancestors only, so a clip’s own background must be the brand colour while its children are free to vary — that is where legitimate visual variety lives.
Contact sheet
A grid of still frames pulled from the video, so a human or model can review it without scrubbing a timeline.
Frame vs second
Colophon authors in seconds; frame rate is a renderer concern. Hardcoding TITLE_HOLD_FRAMES = 100 silently means something different the moment you switch to 60fps.
Authored vs timeline
The authored total is the sum of scene lengths. The timeline total is what the composition actually runs, which is shorter when scenes overlap at their boundaries. The timeline total is the delivery baseline, because it is what ships.
Deterministic
Same input, same output, every time. Why the gates can be trusted and a model’s opinion cannot.
Provenance
The record of what produced what. Every report carries the spec’s hash, so “which spec made this video?” is always answerable.
Seam
A deliberately narrow joining point where one implementation can be swapped for another without the rest of the system noticing.
Live agent row
A bench result that came from really running codex or claude. Marked with * in the table, because it is a record of one real attempt, not a reproducible number.
