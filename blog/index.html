Building Colophon: a deterministic video‑QA agent that runs inside TrueForge

How we made "does this video look good?" a question a computer can answer — without ever asking a model.

By the Colophon team · Built on TrueForge · Apache‑2.0

The problem nobody had solved

An agent can write a video plan in seconds. What it cannot tell you is whether that plan will actually look good. A scene that is 0.2 seconds long. Text that overflows its box. A colour that isn't the brand colour. A claim with no source behind it. These are the things that make a "finished" video feel amateur — and until now, catching them meant a human watching the render and wincing.

We split the problem in two: computer‑catchable defects (timing, overflow, brand colour, unsupported claims) vs. the genuinely human judgement of "does the movement feel cheap?" Colophon solves the first completely, with fourteen deterministic gates. The second stays human — and that's honest, not a failure.

The bet: spec‑first, then lint the spec

You cannot lint a pixel, but you can lint a spec. Our core idea is to stop letting the agent author from nothing and instead give it a closed motion vocabulary to choose from — a finite set of moves, each with explicit parameters. Once motion is a number (400ms, 60ms stagger, scale 1.05), taste becomes a parameter you can set, version, and enforce. A verdict can then be located instead of interpreted: "the pulse feels cheap" maps onto one of three dials, and one edit fixes it for every future video.

Every render also gets a reproducible fingerprint — the spec's hash plus a record of every QA stage — so a result can be replayed and audited, not just admired.

Architecture: Colophon runs inside TrueForge

Colophon is an instrument, not an employee. It reports what is wrong with a video spec; it does not decide what to do about it. TrueForge is the environment an agent works inside — the loop, the tool calling, the sandbox, the approvals, the session state. So Colophon runs inside TrueForge as an MCP tool server, and the agent does the actual work of reading a report and acting on it.

The crucial point: the agent is not asking a model "is this video good?" — on boundary defects that is close to a coin flip. It is calling a deterministic instrument, reading a precise answer that names the gate and the failure code, and acting on it. TrueForge supplies the loop; Colophon supplies the ground truth.

Why this isn't a wrapper

A wrapper would put the model in charge and treat the checker as a suggestion. We did the opposite: the gates hold the veto, the model never does. When a spec isn't ready, a gate says blocked with a specific code — and the agent's only move is to fix the underlying cause. This is why the system is demoable with zero API keys: TrueForge runs standalone, and Colophon's gates make no model calls at all. The ground truth is free; only the agent that acts on it needs a model.

Honesty by design

Three rules keep the system trustworthy: (1) gates make zero model calls — a verdict is computed, not guessed; (2) the taxonomy fails closed — if a gate can't check something because the artifact doesn't exist yet, that's a blocker, not a pass; and (3) an independent review builds a contact sheet a human signs off on. We'd rather be loudly incomplete than quietly wrong.

Lesson Our job was not to read the corpus — it was to smelt it into enums. A blog post is read once; a schema enum is applied a million times. The leverage was in the vocabulary, not the model.

Try it

# serve Colophon's gates as MCP tools
colophon mcp serve --host 127.0.0.1 --port 8000

# in another terminal, start the harness (no signup, local sandbox)
npx @truefoundry/trueforge@latest        # listens on :8790

# or run the whole pipeline headlessly, no agent, no key
python3 -m colophon.cli deliver runs/cadence-01 --review

In TrueForge: Settings → MCP servers → Add, type remote, URL http://127.0.0.1:8000/mcp. Then watch the agent call colophon_validate, hit a named blocker, edit the spec, and re‑run until it's ready.

What's next

The human "does it feel cheap?" judgement is the only unsolved half — and we believe a closed vocabulary makes even that tractable over time. For now, Colophon ships the part a computer can own, and gets out of the way for the part only a person can.

Colophon is Apache‑2.0 and built on TrueForge. Source: github.com/Manancode/colophon-agent-harness.
