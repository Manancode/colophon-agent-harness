Building Colophon: a deterministic video‑QA agent that runs inside TrueForge

Colophon Team · August 2026 · Built on TrueForge · Apache‑2.0

The problem

An agent can write a video plan. Nothing tells it if the plan will look good.

A scene that is 0.2 seconds long. Text that overflows its box. A colour that isn't the brand colour. A claim with no source behind it. These are the defects that make a "finished" video feel amateur — and until now, catching them meant a human watching the render and wincing.

We split the problem in two: computer‑catchable defects (timing, overflow, brand colour, unsupported claims) versus the genuinely human judgement of "does the movement feel cheap?" Colophon solves the first completely, with fourteen deterministic gates. The second stays human — and that is honest, not a failure.

The bet

Spec‑first: lint the spec, not the pixel

You cannot lint a pixel, but you can lint a spec. Our core idea is to stop letting the agent author from nothing and instead give it a closed motion vocabulary — a finite set of moves, each with explicit parameters. Once motion is a number (400ms, 60ms stagger, scale 1.05), taste becomes a parameter you can set, version, and enforce. A verdict can then be located instead of interpreted: "the pulse feels cheap" maps onto one of three dials, and one edit fixes it for every future video.

Every render also gets a reproducible fingerprint — the spec's hash plus a record of every QA stage — so a result can be replayed and audited, not just admired.

Architecture

Colophon runs inside TrueForge

Colophon is an instrument, not an employee. It reports what is wrong with a video spec; it does not decide what to do about it. TrueForge is the environment an agent works inside — the loop, the tool calling, the sandbox, the approvals, the session state. So Colophon runs inside TrueForge as an MCP tool server, and the agent does the actual work of reading a report and acting on it.

The crucial point: the agent is not asking a model "is this video good?" — on boundary defects that is close to a coin flip. It is calling a deterministic instrument, reading a precise answer that names the gate and the failure code, and acting on it. TrueForge supplies the loop; Colophon supplies the ground truth.

Why this isn't a wrapper

The gates hold the veto; the model never does

A wrapper would put the model in charge and treat the checker as a suggestion. We did the opposite: when a spec isn't ready, a gate says blocked with a specific code — and the agent's only move is to fix the underlying cause. This is why the system is demoable with zero API keys: TrueForge runs standalone, and Colophon's gates make no model calls at all. The ground truth is free; only the agent that acts on it needs a model.

Honesty by design

Three rules keep it trustworthy

  • Zero model calls in the gates — a verdict is computed, not guessed.
  • The taxonomy fails closed — if a gate can't check something because the artifact doesn't exist yet, that's a blocker, not a pass.
  • Independent review builds a contact sheet a human signs off on — we'd rather be loudly incomplete than quietly wrong.

Under the hood

What's actually built

Colophon is small and honest about what it owns:

  • Fourteen deterministic gates. Spec‑level gates (vocabulary, parameters, preconditions, source grounding) run before any artifact exists; artifact‑level gates (timing, overflow, contrast, brand‑colour compliance, claim support) run after render. Every gate returns { state, blockers, warnings, hint }.
  • A canonical spec. The spec is the source of truth — a closed vocabulary of moves with explicit parameters. You lint the spec, not the pixels.
  • A bounded repair loop (colophon design). Headless, no agent, no API key: it localizes a failure to one of three dials (vocabulary, parameters, precondition) and applies a targeted spec edit, then re‑runs. Fails closed.
  • Independent human review. colophon review extracts frames into a contact sheet a person signs off on — the only judgement a computer can't own stays human, and it's auditable.
  • A reproducible fingerprint. Every render records the spec hash, each QA stage, and the resolved runtime into delivery‑report.json, so a result replays instead of being admired.
  • Why an instrument beats a model opinion. On boundary‑defect judgement, models score F1 11–42 (UI‑Lens, CVPR 2026) — close to a coin flip. Colophon returns a named gate and a failure code, not a vibe.
  • Ten ADRs. The trades are written down: fail‑closed taxonomy, opt‑in agent invocation, SKIP‑versus‑FAIL honesty, never silently substituting a missing field. tests/test_docs.py fails the build if the prose drifts from the code.
  • Demoable with zero keys. TrueForge runs standalone; the gates make no model calls. colophon deliver runs end‑to‑end from the CLI.

Run it

# serve Colophon's gates as MCP tools
colophon mcp serve --host 127.0.0.1 --port 8000

# in another terminal, start the harness (no signup, local sandbox)
npx @truefoundry/trueforge@latest        # listens on :8790

# or run the whole pipeline headlessly, no agent, no key
python3 -m colophon.cli deliver runs/cadence-01 --review

In TrueForge: Settings → MCP servers → Add, type remote, URL http://127.0.0.1:8000/mcp. Then watch the agent call colophon_validate, hit a named blocker, edit the spec, and re‑run until it's ready.

Where this is going

More corpus, smelt into more enums

The roadmap is to keep converting taste into checkable parameters: additional closed vocabularies for new artifact types, and gates that localize "feels cheap" to a precise, fixable dial. The human taste call stays human; Colophon's job is to make it the only thing left to argue about.
